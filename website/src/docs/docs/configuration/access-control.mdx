shuvmaki checks Discord permissions before processing **any** message, so only trusted people can run agents on your machine. You control access with roles and a per-channel mention mode.

## Who can trigger shuvmaki

A user needs **one** of these to use the bot:

- **Server Owner**
- **Manage Server** permission
- **Administrator** permission
- the **"shuvmaki" role** (case-insensitive)

Messages from anyone without one of these are silently ignored.

```diagram
   message ──▶ has Owner / Manage Server / Admin / "shuvmaki" role?
                       │ yes                         │ no
                       ▼                             ▼
                 process message                 ignore silently
```

The **"shuvmaki" role** is the recommended way to grant team access: create a role named `shuvmaki` and assign it to trusted members. No elevated Discord permissions required.

## Blocking users

Create a role named **"no-shuvmaki"** or **"no-kimaki"** (case-insensitive) to block specific users, **even server owners**. This is useful in shared servers to prevent accidental triggers from people who otherwise have admin rights.

<Aside>
<Tip>
Use a dedicated Discord server for your agents. It keeps coding sessions isolated and gives you full control over who has the shuvmaki role.
</Tip>
</Aside>

## Letting other bots trigger shuvmaki

Other Discord bots are **ignored by default**. To build multi-agent orchestration where another bot drives shuvmaki, assign the **"shuvmaki" role to that bot**. Then its messages are treated like a trusted user's.

## Mention mode for busy channels

By default the bot responds to every message in a configured channel. In a busy or shared channel that can be noisy. Enable **mention mode** so the bot only starts a new session when it is **@mentioned**:

```
/toggle-mention-mode
```

- When **enabled**, only `@shuvmaki ...` messages start new sessions in that channel.
- Messages **inside existing threads are unaffected**; they always continue their session without a mention.

Run the command again to toggle it back off.
